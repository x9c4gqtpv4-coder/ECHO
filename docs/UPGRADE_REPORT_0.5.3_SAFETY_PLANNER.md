# 0.5.3 安全闭环与影子规划器升级报告

## 结论

0.5.3 的目标不是再叠加一个模型，而是保持已确认的 A0 成图逻辑，把新能力变成“可证明、可关闭、可回滚”的附加层。A0 仍是唯一默认像素路径；B1 仍只能通过独立命令生成待复核局部候选；C1 仍没有像素权限。

## 已修复问题

1. **A0 身份闭包不完整**：旧指纹可能漏掉运行时导入的像素函数。现在同时绑定保守模块集、实际函数源码和 Python 字节码；替换 `_bounded_luminance_curve` 会立即改变 A0 指纹。
2. **B1 授权报告可伪造**：不再信任 JSON 中自报的 `usable_for_colour`。`precision-match` 会从标签图、置信度图和完整阈值策略重建蒙版，并与提供的蒙版逐像素比较。
3. **保护对象会被局部追色带色**：B1 增加 `--protected-mask`。其软蒙版与授权权重做乘法扣减，因此书、商标、包或配饰不会被后续羽化重新纳入。
4. **人工批准 TOCTOU 竞态**：审核现在按 SKU 加独占锁，拷贝到事务暂存区后核验，发布前复核原候选/蒙版/证据，发布后再复核已批准文件；任一失败即回滚。
5. **C1 证据门过松**：所有数值阈值均校验。曝光未来候选要求两个可比区域蒙版和 `same_surface`/`human_confirmed` 证据。中性面必须额外通过 OKLab 低色度检查。由于 Duv/Planckian locus 尚未完成验证，CCT/mired 暂不输出。
6. **A0/B1/C1 流程容易越变越乱**：新增确定性 `execution-plan.json`。它只记录能力和前置条件，默认仍选 A0，禁止自动换路，没有像素、否决或批准权限。

这是有意的 fail-closed 工作流升级：0.5.2 或更旧的候选包因没有计划证据，不能直接通过 0.5.3 的批准命令。应在保留旧证据的前提下重算候选，不为旧 JSON 补写伪造的计划。

## 不变的核心逻辑

- 每个 SKU 只追自己的指定场景。
- A0 只分背景与整个人物；服装跟随人物的同一条变换。
- 从原图单次渲染，不叠加多次转码和局部调整。
- 完成自动指标不等于批准；所有成图仍是 `accepted=false`。
- B1 和 C1 均不进入 `sku-pilot` 的像素通路。

## 验证范围

代码包含以下回归与对抗性用例：A0 黄金像素、运行时替换像素函数的指纹失配、B1 修改蒙版且同步伪造哈希、保护区零变化、批准拷贝期候选突变、审核锁、有色表面伪装中性、缺少可比表面证据的曝光候选拒绝。

本机在 macOS / Python 3.12.13 / NumPy 2.3.5 / Pillow 12.3.0 下完整发现并通过 **166 项测试，0 失败，0 跳过**，包含真实 macOS Vision EXIF 几何集成测试。这些测试证明安全契约和程序回归，不能代替真实 SKU 的蒙版准确率、色差和成图美学验收。

## 仍未完成的能力

- 没有真实 SKU 的精细蒙版统计准确率证明。
- 没有物理商品色真值（色卡/已审核商品锚点）的生产标定。
- C1 仍不能作为自动白平衡或自动曝光渲染器。
