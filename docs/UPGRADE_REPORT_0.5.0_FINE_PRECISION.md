# 0.5.0 可选精细识别与部位追色升级报告

> 历史快照：本文件记录 0.5.0 当时状态与测试数字。当前实现和验证结果以 0.5.1 报告为准。

## 结论

0.5.0 增加了真实可调用、但默认关闭的精细能力；没有改动 A0 的参数、颜色数学、Vision 人物蒙版或 SKU 默认入口。

“完美精准自动识别”不能被模型名称保证。生产意义上的精准被拆成三个独立门：

1. **定位证据**：ATR18 标签和逐像素置信度，或人工修正标签。
2. **调色授权**：区域达到像素数、平均置信度和覆盖率阈值；人工版本绑定审核人。
3. **颜色执行**：只读取源图和参考图同名部位的统计，只在源图授权区域内作有界单次变换。

任一门失败，程序拒绝追色。不存在“精细模型失败后用整个人物蒙版凑合”的路径。

## 能力范围

固定 ATR18 类别：背景、帽子、头发、墨镜、上衣、裙子、裤子、连衣裙、腰带、左右鞋、脸、左右腿、左右手臂、包和围巾。另生成 garment、shoes、skin、accessories、person 与 unknown 组合蒙版。

支持：

- 导入自动标签 + 逐像素置信度；
- 导入人工修正标签 + 审核人；
- 本地 SegFormer ATR18 safetensors 适配器；
- 每个部位独立的可用性与失败原因；
- 蒙版、源图、报告三者 SHA-256 绑定；
- 任意同名部位的独立精准追色；
- 区域外像素不变、新增裁切、目标距离前后值与人工复核状态。

不支持或尚未宣称：

- 自动识别 100% 正确；
- 把产品平铺图颜色直接当成上身图的物理真值；
- 未审核权重进入商用生产；
- B1 自动叠加到 23 套 A0 批处理；
- 自动质量批准。

## 画质与边界策略

- 标签边缘只向授权区域内部羽化，不向书、皮肤、包或背景扩张。
- 追色使用 OKLab 区域亮度分位数与稳健色度中心，限制强度、明度增量和色度增量。
- 原像素只解码一次，最终无损母版只编码一次；不串行保存中间 JPEG。
- 授权蒙版为零的像素在输出数组中直接回填原值。
- 候选报告始终为 `accepted=false`；必须视觉检查真实纹理、肤色、反光和边缘。

## Mac 负载

A0 完全不加载精细模型。B1 自动识别默认 CPU、2 线程、最长边 768；全分辨率只保存标签和执行分块颜色变换。模型和 PyTorch 仅在显式调用 `--model-dir` 时加载。可先用自动小图完成标签，再人工复核标签，多张图串行执行。

## 安全与许可证

模型只从本地目录读取，`local_files_only=true`、`trust_remote_code=false`，只接受 safetensors，拒绝 pickle 权重和符号链接。模型必须精确声明 ATR18 的 18 类顺序，否则拒绝运行。

代码许可证、模型权重许可证、训练数据条款和商用权利是四件不同的事。当前仓库不捆绑 ATR18 权重；在许可证确认和真实 SKU 验收前，自动后端只允许隔离测试。

## 验证

本次新增直接测试覆盖：

- 自动标签缺少置信度时失败关闭；
- 低置信度部位不可用于追色；
- 人工标签必须记录审核人；
- 羽化不会授权原区域外像素；
- 非 ATR18 类别被拒绝；
- 精细追色使目标距离下降；
- 区域外像素逐点不变；
- 蒙版被修改后哈希授权立即失效；
- 全套 A0 Golden、文件安全、Profile、缓存、SKU 工作流和 macOS Vision 回归。

本机 Python 3.12.13 完整结果：141 项通过，0 失败，0 跳过。没有实际 ATR18 权重，因此本轮没有声称完成真实模型精度验收。
