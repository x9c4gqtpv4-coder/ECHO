# 0.5.3 逻辑思维导图

```text
一个 SKU：指定场景 + 5~7 张成品动作 + 可选产品图/人工证据
│
├─ 0. 输入与真值契约
│  ├─ 扫描 SKU，图片逐个 SHA-256
│  ├─ sku-profile.json：指定场景/服装锚点/产品证据
│  └─ 不把“已扫描产品图”冒充成“已用于 A0 追色”
│
├─ 1. 影子执行规划器（只写计划，无像素权限）
│  ├─ 输出 execution-plan.json + 指纹
│  ├─ A0 = 唯一默认渲染路径
│  ├─ B1 = 只显示是否具备前置证据，仍不自动启用
│  ├─ C1 = 只读观察，不否决 A0
│  └─ 禁止根据图片“猜一条路”后静默换算法
│
├─ 2. A0 稳定主路（已有 23 套视觉经验）
│  ├─ 背景蒙版 → 本 SKU 指定场景
│  ├─ 整个人物蒙版 → 本 SKU 人物锚点 + 场景方向
│  │  └─ 服装、皮肤、头发跟随同一条人物变换
│  ├─ OKLab、有界变换、从原图单次 float32 渲染
│  ├─ 代码闭包指纹：模块 + 实际绑定函数 + 字节码
│  └─ 输出始终是待复核候选，不自动批准
│
├─ 3. B1 精细部位能力（独立命令，默认关闭）
│  ├─ ATR18：脸/头发/上衣/裤/鞋/包/配饰等
│  ├─ 标签图 + 置信度图 + 阈值策略 → 重算授权蒙版
│  ├─ 不信任 JSON 里自报的 usable/mask 结果
│  ├─ 保护蒙版（书/商标/配饰）只能从编辑权限中扣除
│  ├─ 只做有界局部残差，区域外逐像素不变
│  └─ 新候选仍要独立人工复核
│
├─ 4. C1 冷暖/曝光/色调观察（只读）
│  ├─ 显示参考下的相对增益，不声称拍摄 EV
│  ├─ 曝光未来候选必须：两蒙版 + same_surface/human_confirmed
│  ├─ 显式中性面还必须通过低色度合理性检查
│  ├─ Duv/Planckian locus 未验证前不输出 CCT/mired
│  ├─ 分位点平行度 + 空间稳定性 + 高光/暗部截断门
│  └─ 只写 JSON，pixel_authority=none
│
├─ 5. 发布与人工审核
│  ├─ 候选/蒙版/报告/身份/计划全部哈希绑定
│  ├─ 每 SKU 审核锁，防止同时批准
│  ├─ 先拷贝到事务暂存区再复核哈希
│  ├─ 发布后再校验一次，失败则回滚
│  └─ 只有 sku-review 才能产生已批准成品
│
└─ 6. 证明与交付
   ├─ A0 黄金像素回归
   ├─ 蒙版伪造/保护区/审核竞态/C1 反例测试
   ├─ Linux Python 3.11/3.12 CI 配置模板
   └─ macOS 3.12 + 真实 Vision helper CI 配置模板
```

核心原则：能力可以越来越多，但每个能力都必须有独立证据门、权限边界和回退路径；不允许为了“自动”而暗中改变已证明稳定的 A0。
