# 0.3.1 安全补丁报告

日期：2026-08-27。

本轮修复输入位深、异常 Profile、非有限颜色、空间曲面外推、退化缓存及 CLI 异常边界，并增加整组产物暂存与运行异常回滚。仍为待人工复核的候选生成器，不提供自动批准。

## 1. 实际修改

### 格式与精度

新增 encoding.py，在 Pillow 加载像素之前检查原始格式元数据：

- PNG：IHDR bit depth / color type。
- JPEG：SOF sample precision。
- TIFF：BitsPerSample / SampleFormat；只接受已支持的无符号整数采样。
- WebP：明确限制为现有解码器支持的 8-bit RGB/RGBA。
- 其他格式拒绝，不猜测转换。

高位深 RGB、RGBA、灰度、外部蒙版均会被拒绝。RGBA 测试包含完全不透明、半透明和 Alpha=65534 等接近不透明的情况，防止先量化 Alpha 后误判。ImageInfo 记录 original_format 和 original_bit_depth。8-bit JPEG/PNG/TIFF/WebP 正常路径已复测。

这不是新增 16-bit 调色能力，而是防止不支持的精度无声损失。

### Profile 与运行数值

Profile v4 增加空间可信度诊断。符合约束的 v2/v3 仍可读取，但旧曲面默认不可信，不允许直接启用空间追色。

校验覆盖字段结构、类型、有限性、float32 可表示性、亮度分位点顺序、色度范围、非负 MAD/residual、正整数样本数、有效保留比例、曲面系数、模型阶数、标准网格颜色及梯度范围。元数据也必须能序列化为有限 JSON。

校验不仅用于 from_json，也用于直接 apply_profile API 及 Profile 保存。

调色结果在 clip 和 uint8 量化之前检查 Oklab 与 RGB 的有限性。报告也在交给文件写入流程之前检查序列化合法性。a_median=1e300 现在在加载阶段失败，不生成全黑候选。

### 曲面可信度与模型选择

新增 surface.py。源图与参考图都需要通过空间支撑检查：

| 检查 | 当前工程门限 |
| --- | --- |
| x/y 坐标跨度 | 至少 1.2，完整坐标范围为 -1 到 1 |
| 8×8 网格覆盖 | 至少 25% |
| 象限 | 四个 |
| 设计矩阵秩 | 6 |
| 条件数 | 不超过 1000 |
| 网格最大最近支撑距离 | 不超过 0.9 |
| 距离大于 0.75 的网格比例 | 不超过 15% |

模型按常数、平面、二次曲面逐级比较。采用四组空间块留出，不随机拆散同一窄条像素。复杂模型必须同时达到至少 10% 的相对改善及 0.001 的绝对改善，才替代简单模型；选中模型留出 RMSE 超过 0.05 时禁用空间路径。

这些阈值是保守工程防护，尚不是经用户验收集校准的画质评分。网格距离是近似支撑检查，不是真实场景几何重建。

门未通过时回到 global；显式 --path surface 也不能绕过。auto 不再在两个未通过内部检查的结果中优先选择复杂曲面。只剩全局候选时仍标记 review，不冒充合格。

回归测试还发现纯色输入不能可靠拟合七段分位曲线。该退化情况改用固定黑白端点、单调、有界的简单中位数映射，避免近似无差异时反而多改约五个灰度值。

### 运行级产物提交

新增 transaction.py。单图和批处理都采用：

1. 完整路径防护及协作锁。
2. 在隐藏的单次运行目录暂存 candidate、mask、preview、可选 Profile、report。
3. 图片复读、像素/哈希检查、最终报告序列化。
4. 备份已有输出，写入并同步恢复日志。
5. 发布产物，最后提交报告；普通异常时恢复旧产物或撤回本次新产物。

单图失败另写 .batch-color-errors 中的 error JSON；批处理失败写 errors 中的记录及汇总。正常失败不再留下 processing 报告，也不会先发布黑图再因报告报错。

重要限制：任意多个文件路径不能通过一次 rename 获得物理原子性。本版是应用层暂存、锁、备份、回滚及报告最后提交协议，不是数据库式事务。

突然断电、SIGKILL、回滚期间磁盘再次故障，仍可能留下暂存、备份、锁或需要恢复的路径。必须保留恢复日志，确认进程停止后人工检查；自动恢复命令尚未实现。下游必须验证完整报告与所有产物哈希，不能只监视候选文件名。

本轮测试了候选、蒙版、报告发布阶段的故障回滚，包含新输出和替换已有输出；没有声称验证了所有断电与文件系统故障。

### 缓存与异常边界

缓存 schema 升为 4。记录实际 mask backend、fallback_reason 和 cacheable：

- auto 请求发生 Vision 运行失败或超时：该退化候选不允许长期命中，下次重试。
- 用户明确指定 heuristic：允许缓存。
- 环境没有 helper：允许缓存；以后新增 helper 会改变缓存身份。

成功恢复到 Vision 后可以再次缓存。缓存命中仍为 review，退出码仍为 3。

Profile schema 错误统一为 ValueError；CLI 捕获预期的 subprocess 错误。空 Profile 和显式 Vision 超时不再向用户抛出 traceback。

## 2. 验证结果

现有及新增测试合计 84 项，包括真实 macOS Vision EXIF 集成测试。最终测试日志及结果保存在本机 verification.json 和 unit-tests-final.log。

重点反例结果：

- 16-bit RGB / RGBA：解码前拒绝；源文件哈希不变。
- a_median=1e300：加载失败；没有新黑图或 processing 报告。
- 运行中注入 NaN RGB：量化前拒绝。
- 窄条参考：原反例输出 129～192；本版输出均匀 160，surface 被禁用。
- Vision 临时失败后恢复：第二次实际重试，恢复后的第三次可缓存。
- 空 Profile / Vision 超时：受控错误码 2。
- 故障发生在整组暂存或发布期间：新产物不残留，已有完整输出保持原内容。

### 用户提供的两组图片

两组图片均重新生成 background 和 both 候选，共四次运行，保留原尺寸和 8-bit sRGB 无损输出。没有覆盖原图或旧候选。

| 图片 | 路径 | 内部背景距离变化 | both 色域裁切比例 |
| --- | --- | --- | --- |
| 01 全身 | spatial-surface | 2.7812 → 0.6658 | 0.0130% |
| 02 近景 | global-monotone | 5.9738 → 5.7199 | 1.3132% |

距离是自定义 Oklab 背景统计量，不是 ΔE2000，不是独立画质分。第二组曲面被可信度检查禁用，追色幅度比旧实验结果更保守；不能据此宣称效果更接近目标或人物追色已完成。

两个 background 结果的蒙版零值核心区都逐像素等于规范化输入。所有结果 accepted=false。

额头和颈部进行了原尺寸对照及差分检查。both 结果的差分梯度 P99 分别为 3 和 2 个 8-bit 通道值/像素。它们只是诊断值，不是无色块认证；ROI 包含眼镜、发丝或衣领，新零值通道仍存在。

四次单图运行约 2.3～2.7 秒；采用两线程限制、串行执行，并使用本机 Vision。此时间不是冷启动或任意尺寸保证。
