## 2. 修改后的实际路径

输入文件先经过格式和元数据检查、EXIF 一次转正、ICC 转为 sRGB，得到规范化图像。Vision 读取该图像的临时无损副本，不再重新对原始附件采用另一套方向处理。

源图/参考图背景蒙版进入取样和曲面估计。蒙版核心区域不足时停止该图片的处理，不无声地忽略蒙版继续拟合。旧 v2 Profile 仍能读取，但会记录边缘统计限制；新 CLI 生成 v3。

系统生成背景空间曲面与全局曲线两个候选，比较内部背景指标。通过内部指标只能标记 baseline_checks_passed，不能升级为正式批准。

最后应用模式授权和保护蒙版、量化、无损写出并重新读取。候选和报告完整写出后才可形成缓存记录。批处理保存在 candidates，而非声称已合格的成品目录。

这种路径比旧版本明确，但背景统计仍不是独立肤色目标，背景蒙版也不是商品语义识别。

## 3. 亮度反向的修正及实际回归

旧人物分支将随输入亮度变化的“暗部保护”乘到亮度差上。即使基础曲线单调，组合后的最终映射也可以反向。独立灰阶反例在 0.2.0 中有 16 次下降，内部仍 accepted=true。

本轮分开处理：

### 背景曲线

在密集一维网格上限制并平滑斜率，再积分形成有界单调映射。限制强度在 0..1，避免超出凸混合范围。平滑只作用于一维映射，不对照片进行磨皮或图像模糊。

### 人物曲线

采用黑白端点固定的有界映射：

`f(L) = kL / [1 + (k-1)L]`

k 由背景亮度中位数的相对变化推导，并限制在 0.5..2。该函数满足 f(0)=0、f(1)=1，导数为正且有限；不再通过会造成反序的亮度相关保护权重混合。

色度偏移在极暗和极亮处平滑减弱，避免把纯黑/纯白直接染成背景偏色。这仍是实验性整体色调调整，不是肤色标准学习。

### 修复中发现并处理的回归

第一轮直接取消旧权重后，虽然灰阶反向消失，但第一组真实图片的深蓝牛仔裤被抬灰。该候选没有被当作最终结果；随后引入上述黑白端点固定的人物曲线，并增加黑白不被抬灰的回归测试。

最终灰阶反例下降次数为 0。测试覆盖不同背景权重、global/surface 路径及多个强度。该结论只针对已覆盖条件，不能推广成所有色彩、空间边界和编码条件的绝对保证。

## 4. 区域授权的实际含义

默认 background 模式：

- 只调整背景蒙版允许的区域。
- 背景蒙版为 0 的像素在最后直接恢复为规范化输入像素。
- 原图背景是否分割正确仍需要检查，不能声称所有真实人物像素都已被识别并保护。

both 模式：

- 用户显式启用人物整体调整实验。
- 人物会改变颜色，未指定保护蒙版的衣物也可能改变。
- 不能把这个模式叫“商品原色自动保护”或“皮肤独立追色”。

protected-mask：

- 白色=完全保护，黑色=允许调整，灰色=减弱调整。
- 在无损输出复读后，测试中的保护核心区域逐像素等于规范化输入。
- 支持单图 match/apply；批处理尚未增加逐图商品保护蒙版映射。
- 外部蒙版尺寸必须与转正后的图像一致；尺寸错位会报错，不擅自缩放。

这是明确的保护能力，不是自动发现商品、皮肤和头发的能力。

## 5. 文件、缓存与状态修正

### 文件安全

在写任何产物前预检完整路径集合。即使主输出路径安全，preview、report、mask-output、profile-output 也不能指向原图或参考图。同样，输出之间不能相互覆盖。

对已有文件同时核对规范路径和文件身份，能拦截不同路径的硬链接。对路径大小写和 Unicode 采用保守冲突检查；符号链接输出被拒绝。单图覆盖已有输出需要显式 overwrite，它不能绕过输入保护。

各文件先在同目录临时文件写入并校验，再替换目的文件。批处理使用报告作为完整缓存记录的提交标记，不能把部分写出的文件当作成功运行。单文件原子性不等于多文件事务；中途失败可能留下明确属于候选区的部分产物，下次必须校验和重算。

### 缓存

签名包含输入内容、Profile 内容和路径、参数、源码文件哈希、依赖版本、系统信息、原生分割程序哈希以及输出策略。缓存复用前还核对候选、蒙版和必要预览的文件哈希。

文件命名保留输入扩展名，避免 same.jpg 和 same.png 共用 mask/report。本版不再仅凭尺寸单独复用旧蒙版；更细粒度的安全蒙版缓存可后续实现。

改变配置时会在相同输出位置重算候选。旧 corrected 目录和旧格式报告不作为新缓存，也不会自动删除。

### 状态

- status=review：仍待复核。
- computation=processed/cached：本次是否重新计算。
- baseline_checks_passed：内部背景条件是否满足。
- no_op：最终像素是否不需要改变。
- accepted=false：当前不授予自动生产批准。

因此 cached 不会消除 review。已经达到标准的图允许 no-op，不为了制造“改善百分比”强行改图；它仍不等于获得完整质量认证。

## 6. 输入与精度限制

本版明确支持单帧 8-bit 图像归一到 sRGB。有效 ICC 会转换，缺失 ICC 的普通 RGB 记录“假定 sRGB”；坏 ICC、无 ICC 的 CMYK/LAB、透明度、未支持高位深及多帧输入被拒绝。

高位深支持尚未实现，拒绝降位深不等于已具备 16-bit 工作流。PNG/TIFF 无损导出也仅保证当前已计算的 8-bit 像素不再被 JPEG 压缩，并不意味着整个调色过程“无损”。

主图限制 PNG/TIFF；预览可用 JPEG。无损主图写出后重新打开，验证尺寸、模式、ICC 和像素一致性，并记录哈希。色域裁切目前仍存在，报告如实记录，不将其隐藏为“完全安全”。

## 7. 本轮验证结果

### 自动测试

当前本机共 55 项测试通过，0 失败、0 错误、0 跳过。包含实际原生 Vision 的 EXIF 几何集成测试；没有构建原生 helper 的其他环境会跳过该项。

覆盖重点：

- 所有 CLI 输出角色对输入的覆盖防护。
- 硬链接、符号链接、大小写和父子路径冲突。
- 单文件写入失败时保留旧文件。
- 源/标准/参数/源码变化使缓存失效。
- 同名不同格式独立蒙版与报告。
- 产物损坏、残缺报告及中途失败不形成合法缓存。
- 缓存后的复核状态、退出码和目录写入互斥。
- 8 种 EXIF 方向、规范化像素送入原生程序、错误尺寸拒绝。
- 透明度、高位深和坏 ICC 拒绝。
- 单调映射、黑白端点、显式保护、分块一致性、no-op。
- 蒙版排除接触边缘的人物对背景统计的污染。

通过数不等于覆盖率，本次没有提供或假称代码覆盖率百分比。

### 用户提供的两组图片

两组均按 both 实验模式、0.85 强度、当前双图背景统计流程生成原尺寸无损候选，并查看了整体对照。

| 测试 | 输出尺寸 | 自定义背景距离变化 | 内部改善 | 正式批准 |
| --- | --- | --- | --- | --- |
| 01，全身图 | 1086×1448 | 2.7812 → 0.5790 | 79.18% | 否，review |
| 02，近景图 | 1772×2363 | 5.9738 → 4.8918 | 18.11% | 否，review |

这些是内部 Oklab 统计距离，不是 ΔE2000，不是独立质量分，也不证明人物颜色已经与参考一致。第二组距离仍明显未收敛，不能作为“最优追色完成”的证据。

近景图另跑 background 模式：背景蒙版为零的 2,238,784 个像素，最终无损文件相对规范化原图最大通道差为 0。该证据验证蒙版契约，而不是验证所有语义区域识别准确。

额头/脖子做了 1:1 局部对照与差分检查。最终 both 候选的变换差分梯度 P99 分别为 3、2 个 8-bit 通道值/像素，梯度余弦相似度约 0.9968、0.9983。这些量只作诊断，没有经过质量门校准；ROI 还包含头发、眼镜或衣领，不能当成纯肤色测试。新零值通道仍存在，因此不承诺没有局部暗部损失。

本次原图和参考图的运行前后哈希一致。

### 本机命令与资源

本机曾仍运行普通安装的旧 0.2.0，现已更新为 0.3.0。验证了安装包中的 Python 模块与工作区源码哈希一致。可编辑安装的 .pth 在该环境被隐藏后会被 Python 忽略，因此最终采用普通安装，没有改动系统运行时设置。

实际安装命令批处理：

- 首轮：2 张 processed，2 张 review，0 error。
- 复跑：2 张 cached，仍为 2 张 review，退出码仍为 3。

本轮两次最终单图运行约 1.6 秒、2.5 秒，进程峰值 RSS 约 297 MB、448 MB；使用 VECLIB_MAXIMUM_THREADS=2，复用了已生成的源图蒙版，参考图仍由 Vision 处理。这不是冷启动、任意分辨率或整机总内存保证。

没有新增第三方依赖或下载模型；继续使用原有 NumPy、Pillow 和系统 Vision。

## 9. 下一步与停止边界

本轮可确认的是“已复现缺陷被修复，失败不会被当成正式批准”，不是“已完成精确全人物追色”。
