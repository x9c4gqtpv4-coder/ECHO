# 0.4.2 工作流与产品证据闭环审计报告

## 结论

0.4.1 的最准确定位是“同一 SKU 套图视觉统一引擎”，不是“精准商品色标准化产品”。用户提供的审计对这个核心结论的证据充足，合成反例也正确证明了“整个人物距离无法唯一识别服装色”。反例不能推导真实生产失败率，但足以否定“整个人物通过就等于服装色通过”。

0.4.2 因此只做 **Workflow and Product-Truth Closure**：保留 A0 已验证的两区单次渲染路径，不启用新模型，不把产品图偷偷变成调色目标，不声称已完成 SKU Color Fidelity。

## 对审计证据的裁定

| 审计主张 | 裁定 | 核验依据 |
|---|---|---|
| A0 锚点和套系一致性是 whole-person，不是 garment-only | 成立 | 默认管线的人物统计、锚点和套系距离都使用整个人物区域。 |
| `garment_stats` 在 A0 中是人物统计别名 | 成立 | 0.4.1 直接赋值 `source_person`。0.4.2 已删除该误导性别名，显式称 whole-person anchor。 |
| 产品图只扫描/哈希，未用于目标计算 | 成立 | 0.4.1 没有在 A0 目标计算消费产品图。0.4.2 把它纳入持久 Profile 证据校验，仍明确为 `evidence_only`。 |
| 没有集成的人工批准记录 | 成立 | 0.4.2 新增候选哈希校验、批准/驳回记录、审核人/原因/时间和去识别共享报告。 |
| A0 运行兼容性只检查 3 个参数 | 成立 | 0.4.2 增加核心函数指纹、依赖版本和 Vision helper 哈希。 |
| 候选成功和质量状态混在退出码 3 | 成立 | 0.4.2 默认生成成功返回 0；需要旧 CI 语义时显式使用 `--strict-quality-exit`。 |
| 语义蒙版直接测试太少 | 成立 | 代码中确有证据不足时返回全图支持的 fail-open 路径。0.4.2 改为全零 fail-closed 并增加直接单测。 |
| 没有 LICENSE、GitHub CI、GUI | 成立 | 本版增加 Python 3.11/3.12 GitHub CI。LICENSE 类型属于权利人的发布决策，未自作主张；GUI 不是精度前置条件，未加入。 |

## 对测试报告的更正

用户附件中 Linux / Python 3.13.5 的 `126 passed, 1 skipped` 是有价值的补充证据，但 Python 3.13.5 不在项目声明的 `>=3.11,<3.13` 范围内，且跳过了 macOS Vision 原生集成测试，不能作为主验收环境。

本次审计在当前 Mac / Python 3.12.13 / Apple Silicon / Vision helper 可用的受支持环境中直接执行完整测试：发现 134 项，134 通过，0 失败，0 跳过，包含真实原生 Vision EXIF 几何集成测试。运行命令为 `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v`。

## 0.4.2 已实施优化

1. `sku-profile.json`：持久记录指定场景、全部产品图证据、候选/已确认服装锚点和 A0 能力边界。任一证据像素改变都使 Profile 验证失败。
2. `待复核候选/` 与 `已批准成品/`：文件夹名不再在审核前称“成品”。
3. `sku-review`：批准前重算每张候选哈希，记录候选、蒙版束、输入清单、SKU Profile、A0 基线和运行身份。
4. `run-identity.json`：绑定发行版、Git commit/工作区状态、Python/依赖、操作系统/架构、源码哈希和原生助手。
5. `历史/`：重算时保留上一版 summary、manifest、profile、identity、审核状态、报告和联系表；不重复大尺寸候选/蒙版/预览，降低 Mac 磁盘压力。
6. 退出状态分离：执行失败为 2，候选成功默认为 0，显式严格质量状态为 3。
7. 语义证据 fail-closed：没有足够 seed 时不再授权全图修改。
8. GitHub CI：在声明支持的 Python 3.11 和 3.12 上执行源码测试。Linux 无 Vision helper 时的跳过不替代 Mac 本地集成验收。

## A0 不可破坏契约

- 背景与整个人物两个软蒙版。
- OKLab 内的有界亮度/色度调整。
- 原图 float32 单次渲染，不串行重复编码。
- 服装跟随 whole-person 变换，不添加第三条未验证的服装路径。
- Golden 像素输出和 A0 参数契约保持不变。

## 仍然没有完成的 B1

0.4.2 不能依据产品图自动把服装调成物理准确颜色。达到该目标需要独立的 `B1 SKU Color Fidelity`：

- 可复核、可人工覆盖的 garment-only 蒙版；
- 产品图或标准成品图与生成图之间可比较的服装区域对应；
- 在 A0 结果上计算、但仍从原像素一次渲染的小强度残差；
- 服装专属的色差、纹理、高光/阴影和边缘 QA；
- 按 SKU 分层的真实验收集和人工批准阈值。

只有 B1 在真实 SKU 验收集上证明服装色更准且不会造成人脸、发丝、纹理、边缘或背景回归后，才能作为默认能力候选。

## 交付边界

- 本版可进入内部封闭工作流测试，不是无人审批的全自动发布系统。
- `baseline_diagnostics_passed=true` 只表示 A0 风险诊断没有触发，不是质量批准。
- 项目仍没有 LICENSE。是否开源、采用哪种许可证必须由权利人决定。
- 终端 CLI 已能完成核心闭环，GUI 可在状态和 B1 数据契约稳定后再建，不应反过来驱动算法。
