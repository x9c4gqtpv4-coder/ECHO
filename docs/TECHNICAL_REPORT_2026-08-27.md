# 批量校色：完整技术方案、缺陷审计与源代码交付报告

版本：2026-08-27 技术交付版。适用源码：0.2.0 基线及本次新增诊断/交付工具。

> 历史记录：以下内容不再代表当前运行版本。0.3.0 已修复项、复测结果和剩余限制见 [修正报告](REPAIR_REPORT_2026-08-27.md)。旧内容保留供审计对照。

## 0. 先给结论

本项目要实现的不是“让颜色看起来改变了”，而是：在保留原图内容、商品本色和自然层次的前提下，把指定区域的色彩表现向经过确认的参考标准靠齐。

用户新增硬性要求：禁止因校色新增或明显放大色块、分层、断阶、脏色、色边和不自然过渡。特别检查额头、脸颊、下巴、颈部、手臂等皮肤区域，以及头发与背景的交界。

这项要求必须高于“追色分数提高”。出现问题的候选不能被一个较好的平均分抵消；检测缺失或不确定时不能自动放行。

**当前0.2.0不满足这一生产验收要求。** 当前源码能运行、生成原尺寸图片和批量报告，但没有实现完整的人物对应区域追色，也没有专门的色块/分层自动拦截器。本次交付不会把尚未实现的保护功能写成已经完成。

本次实际变更：补充局部过渡诊断脚本、可复现测试、源码导出工具，以及修正过度概括的文档。**没有改写主调色算法，没有宣称已消除截图中的问题。** 在完成下述验收前，当前输出只能作为实验候选，由人工复核，不能按 `accepted=true` 直接认定可交付。

## 1. 目标、范围与不可混淆的概念

### 1.1 输入与输出

输入包括：原图、参考图或已确认的色彩标准、需要调整的区域、需要保护的区域，以及允许改变的幅度。

输出包括：不覆盖原图的候选成图、区域蒙版、对比图、质量报告和可追溯的参数。经过验收后才能产生“可交付成图”。

目标区域应支持背景、皮肤、头发、整个人物、自定义局部，以及它们的组合。服装、鞋包、首饰默认属于受保护商品；仅在用户明确要求商品改色时才允许改变固有色。

### 1.2 追摄影色调不等于替换商品颜色

不同照片中的奶油白针织衫与冷白衬衫，不一定是同一种白色被不同光线照亮。蓝色牛仔裤和米色格纹裤更不是颜色对应物。不能通过全图直方图匹配把前者改成后者。

皮肤和头发也存在固有色、妆容、染发、照明差异。需要明确区分：

- 统一拍摄风格：保留人物本身合理的颜色差异，主要匹配曝光、色温、对比关系。
- 明确局部改色：例如用户指定把发色改成参考中的金色；这是更强的编辑目标，必须单独授权并验收。

如果没有色卡、同一商品的标准照片或可靠的拍摄资料，就不能从两张不同内容的照片唯一推导出“真实颜色”。系统应承认这个边界。

### 1.3 “最优”的实际含义

没有脱离目标和约束的唯一最优图。工程上可实现的是：在有限候选中，先满足画质与商品保护约束，再选择匹配最好、修改最小、风险最低的结果。没有合格候选时，正确结果是“需要复核”，而不是强行交图。

## 2. 已经验证的事实

| 不调整 | 2.07 | 5.97 | 2.59 | — |
| global / 0.55 | 1.28 | 5.78 | 2.27 | 通过 |
| global / 0.85 | 0.90 | 5.76 | 2.19 | 通过 |

这些数字是Oklab分布诊断值，越小越好；不是ΔE2000，也不是完成率。独立检查使用高置信背景蒙版，但蒙版不是人工真值，姿势和构图差异也会影响分布。因此不能把其中某一列当作绝对审美标准。

### 2.2 人物参考信息未被充分使用

隔离实验仅改变参考图中部303,959个人物像素，保留边缘采样带；Profile完全不变，输出逐像素不变。变更只发生在内存中，没有改动参考文件。

这证明当前机制没有按这些人物区域去读取参考色彩。边缘上的头发、衣服可能通过污染背景样本影响结果，但那不等于人物对应区域追色。

### 2.3 空间背景拟合混入人物

按本轮Vision蒙版判断，原图空间曲面拟合的原始边缘样本中，约26.95%落在人物上；参考图约10.75%。这是拟合前的原始样本比例，不是稳健拟合后的人物有效权重。

诊断实验保持拟合方法不变，仅从边缘训练样本中剔除人物，再在未参与拟合的内部背景上检查误差：原图从9.96降到1.59，参考图从6.37变为6.42。

原图侧明显改善，支持“人物采样污染是问题之一”。参考图侧没有改善，说明有限的边缘观测和简单曲面仍不能充分解释内部背景。不能声称只修蒙版就能解决全部问题；需要进一步检查模型复杂度、局部照明与空间对应。

### 2.4 额头与颈部截图的核对边界

本次按用户指出的位置，导出了同一原图与auto结果的原尺寸局部对照，以及明确标注“差分放大12倍、并非成图”的变化图。没有直接用低分辨率截图判断全部异常来源。

- 额头周边框：源图坐标(350,80)-(690,335)。
- 颈部周边框：源图坐标(450,590)-(850,940)。
- 这些是人工指定的检查框，也包含部分头发、眼镜或衣领，不是纯皮肤分割。
- 原图已经包含自然阴影；不能把所有阴影或块状观感都认定为新生成的缺陷。
- 小平均差值或较高梯度相似度也不能证明“没有分层”。缺少专项检测时仍须复核。

可以确认的风险是：当前基于背景分位数建立的分段线性亮度映射，区间斜率约0.35到3.24；考虑0.85强度和现有人物暗部权重后，数值估算的有效人物亮度斜率约0.44到2.76。它在相邻亮度区间压缩与拉伸层次的程度差异很大，存在放大不自然过渡的机制风险。**这不是对截图中每个可见色块的单一根因证明。**

## 3. 当前源码实际做了什么

当前流程如下，不能把后文设计当成这一流程已有的功能：

```text
原图、参考图
  → 读入8位RGB并按嵌入ICC转换为sRGB
  → 从参考图边缘提取背景分位数与二维二次曲面
  → 对原图调用Vision，获得人物/背景软蒙版
  → 从原图边缘估计背景差异
  → 背景使用空间曲面差；人物使用背景推导的整体参数
  → Oklab运算、RGB越界硬截断、量化回8位
  → 依据背景改善和截断率判断路径是否通过
  → 保存图片、蒙版、预览和报告
```

| 文件 | 当前职责 | 关键边界 |
| --- | --- | --- |
| `image_io.py` | ICC转换、读写与代理图 | 8位RGB；不是16位完整流程 |
| `color.py` | sRGB与Oklab转换 | 不是ΔE2000实现 |
| `profile.py` | 背景分位数、稳健二次曲面、JSON标准 | 没有皮肤/头发目标；分析未用双图蒙版 |
| `masking.py` | 调用Vision辅助程序，必要时退回颜色启发式 | 不区分皮肤、头发、衣服 |
| `segmentation.py` | 棚拍背景颜色启发式 | 白衣与背景相近时可能失效 |
| `transfer.py` | 两条调色路径、混合与简单评分 | 不是全面候选最优搜索；缺乏过渡专项门控 |
| `batch.py` | 串行处理、缓存、跳过和汇总 | 缓存尚未按内容/参数签名校验 |
| `preview.py` | 缩小的双联/三联JPEG | 不能作为原尺寸画质验收文件 |
| `cli.py` | doctor/profile/match/apply/batch命令 | 目前没有skin/hair/background-only精确模式 |
| `tools/person_mask/main.swift` | 原生Vision人物分割 | 只有人物概率蒙版；并非完整人像解析 |
| `scripts/audit_skin_transition.py` | 本次新增：指定区域的原图/输出差分检查 | 诊断工具，不是自动色块检测或审批器 |

当前实际没有集成CanonCGT、ColorTransferLib、POT、SCHP、BiRefNet等项目的运行引擎。它们属于此前讨论的备选方向，不应出现在“当前已经实现”清单中。

## 4. 不允许出现的问题及判定原则

### 4.1 色块

原本平滑或自然的肤色区域，被变换引入局部偏黄、偏红、偏绿、发灰或突兀的色团。要检查相对于原图新增的变化，不能把原有腮红、阴影、皮肤纹理一概抹平。

### 4.2 分层与断阶

原有连续渐变出现明显的等色带、阶梯或轮廓线。来源可能包括源图已有量化、强曲线压缩、通道硬截断、低精度中间文件、蒙版量化、预览缩放或JPEG编码，不能先入为主只归因于某一项。

### 4.3 不自然过渡

额头到发际线、脸到颈部、亮部到阴影、人物到背景的颜色变化不再连贯。需要同时检查颜色变化场、蒙版边界和原有照明关系。

### 4.4 硬性约束

- 不得覆盖原图。
- 未授权区域的像素应保持不变；这一约束以规范化后的工作图为基准，并在无损导出后复验。JPEG重新编码无法保证逐像素不变。
- 不得用磨皮、降噪或生成式重画来掩盖调色缺陷。
- 不得为了匹配颜色抹掉衣服织纹、毛孔、发丝、阴影立体感。
- 不得将“缺少检测”解释为“检测通过”。
- 皮肤过渡出现可疑异常时，不能仅凭背景分数较高放行。

任何自动检测都可能漏检。因此“禁止”是工程验收与放行规则，不是声称能数学保证所有未来图像都绝无伪影。未校准自动检测之前，人工复核是必须保留的环节。

## 5. 修订后的总体架构（以下为待实现设计）

```text
输入与标准登记
  → 方向/ICC/位深校验
  → 原图与参考图同时分区，记录置信度
  → 对应区域匹配与商品保护策略
  → 估计少量、受约束的候选变换
  → 代理图筛选，但不在此直接批准
  → 原尺寸渲染 + 过渡/边缘/纹理/颜色专项检查
  → 合格候选排序
      ├─ 通过完整验收 → approved
      ├─ 检测缺失或证据不足 → review
      └─ 明确违反约束 → rejected
```

实现时先建立可验证的最小闭环，不以集成项目数量作为进度。核心是区域对应、受约束变换、独立验收与可追溯性。

## 6. 色彩与精度设计

### 6.1 输入规范化

读取EXIF方向、ICC、位深、透明度和尺寸。图像与所有蒙版使用同一方向规范。当前Swift分割会处理方向，Python读图尚未显式做EXIF转正，方向不同的文件存在对齐风险，必须补测试。

缺ICC或损坏ICC时记录来源不确定性，不静默当作可靠标准。参考是显示器ICC的截图或导出文件时，应允许预览比较和人工确认；不能假定它就是相机原始色彩标准。

### 6.2 处理精度

拟定处理原则：以浮点数据保存中间结果，仅在最终编码时量化。当前计算局部使用float32，但读取、蒙版和导出仍为8位，不能因此称为“全流程高位深”。

高质量母版拟支持真正16位RGB TIFF/PNG，并验证ICC与重新读入的一致性。这需要合适的多通道16位I/O后端；仅把Pillow的RGB图片保存成TIFF不会自动成为16位RGB。Pillow官方文档明确其RGB模式为3×8位，并说明多通道高于8位支持受限。[Pillow模式说明](https://pillow.readthedocs.io/en/stable/handbook/concepts.html#modes)

把8位输入转成16位不能恢复已丢失层次，但可以减少后续多次运算量化带来的额外损失。最终8位发布图仍需单独检查，不能用16位母版通过来替代发布文件验收。

### 6.3 色域处理

当前`clip(0,1)`会把越界通道压在边界上，可能破坏色相或层次。设计中应限制变换幅度，必要时进行有界色度压缩，并单独检查皮肤与商品区域。

色域映射也可能改变颜色，因此它是受约束的折中，不是无损修复器。对超出目标色域的目标颜色，必须报告不可完全复现，而不是隐瞒截断。

## 7. 蒙版、对应区域与取色

### 7.1 双图蒙版参与全部环节

原图与参考图的蒙版应参与取样、参数估计、变换应用和独立评分，而不是只用于最后拼合。背景统计应从可靠的背景核心区采样，排除人物、混合边缘、阴影异常与已知水印。

边缘样本不足时不能大范围外推而不报告置信度；有背景的空间位置与被人物遮挡的位置应分别标记。半身图与全身图不能简单按同一归一化坐标复制所有背景照明。

### 7.2 人物局部分区

需要皮肤、头发、上衣、下装、鞋、包及自定义区域。为了先验证颜色算法，可先让少量样本使用人工确认蒙版或取色区域；证明局部映射有效后，再接自动语义模型。

脸、颈部和手臂需要关联建模：保留原有明暗关系，不应把三个部位独立匹配到同一个均值后造成拼接感。发丝边缘需要软蒙版和颜色污染检查，不能简单扩大羽化宽度。

### 7.3 不确定性处理

不同对象没有对应关系、参考区域太小、边缘混合严重、多人重叠、遮挡或蒙版置信度不足时，进入review。不得自动把“没有识别到皮肤”当作皮肤已经安全。

## 8. 候选算法：优先少量、可解释、可约束

### 路径A：轻量整体/区域曝光与白平衡

适用于拍摄条件相近、差异主要来自曝光和色温的场景。采用小幅、正则化的变换，保留原图局部结构。人物参数必须由人物对应区域决定，不能继续全由背景推导。

### 路径B：平滑单调亮度曲线与受限色度变换

适用于明暗关系与颜色倾向不同、但不需要重构图像内容的场景。亮度曲线要求单调、平滑，限制局部斜率及斜率变化，避免大段层次压缩后又继续陡增。

可评估PCHIP等保形插值作为候选实现。其一阶导数连续、保持输入单调性，但二阶导数仍可能跳变；它本身不保证无色带，也不会自动解决不合理目标控制点。[SciPy PCHIP说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.PchipInterpolator.html)

所有斜率上下限、曲率限制、色度变化上限都应由真实样本与合成渐变测试校准。不能把未经验证的固定数字包装成“行业标准”。

### 路径C：仅背景的低频空间颜色场

用于可靠背景区域内的渐变差异，加入空间平滑与幅度约束，限制外推。先比较常数模型、简单平面与更复杂曲面，复杂模型只有在独立背景样本上确实更好时才采用。

不得把这一空间场直接作用到脸、颈部或服装上。源图人物占比过高、参考存在局部不均匀、空间对应不可靠时，应退回受限简单变换或复核。

### 暂不作为主流程的能力

Optimal Transport、全图分布匹配、神经参考风格模型都可以在后续作为隔离实验，但不能直接绕过商品保护与过渡门控。本次不下载新模型、不依赖CUDA，也不宣称某一个模型能保证精确追色。

## 9. 过渡与画质门控设计

### 9.1 比较对象必须正确

追色程度比较“输出对应区域”和“参考对应区域”；纹理、结构与新增伪影比较“输出”和“原图”。两张不同姿势照片不能直接整图做逐像素误差或SSIM来评定追色质量。

ΔE2000只在正确转换到CIELAB、且有意义的对应颜色样本上使用，不能把Oklab欧氏距离重新命名为ΔE2000。

### 9.2 需要新增的专项检查

1. 色块：在可靠皮肤区域计算颜色变化场，检查原图没有的低频突变和局部色偏团块。
2. 分层：在原图平滑渐变区检查输出新增的平台、阶梯和等色轮廓；同时排除原图本身的纹理和量化。
3. 不自然过渡：检查变化场的一阶/二阶变化、曲线控制点附近的响应，以及脸/颈/手臂交接处的关系。
4. 边缘：比较人物边界两侧的颜色泄漏、光晕和发丝污染；定位蒙版混合像素，不只看全图平均。
5. 纹理：比较同一位置的高频与梯度结构，分开报告对比度变化和结构损失，不能只用一个相似度数字。
6. 截断：分别记录亮部/暗部、各通道、皮肤及商品区域的新截断，而非只看整图百分比。
7. 未授权修改：对明确保护且非混合边缘的区域检查像素变化，记录失败区域。

这些检测都需要阈值校准与人工真值，且可能产生误报。它们是设计清单，不是当前已经存在的代码。

### 9.3 放行状态

拟定状态为`candidate`、`review`、`rejected`和`approved`。`approved`必须绑定输入哈希、参数、蒙版、检测器版本、完整检测结果与必要的人工批准。

只要任何必需检测没有执行、失败或无法判定，就不能进入approved。人工确认发现色块、分层或异常过渡时必须拒绝，不能为了提高批量通过率调整分数掩盖问题。

全部候选不合格时保留原图及失败报告；不把原图复制成“校色成功”，不把失败候选放入可交付目录。

## 10. 标准Profile与候选选择

下一版Profile应保存：版本、参考内容哈希、ICC与方向、目标区域及取样、区域置信度、亮度/色度统计、商品保护策略、允许幅度、验收策略版本和人工确认记录。

参数变化必须生成新版本。多人或不同肤色场景不能仅靠一个固定肤色均值覆盖所有情况。

候选选择顺序应为：

1. 先检查输入与蒙版是否足够可靠。
2. 生成有限的可解释候选及强度。
3. 在代理图上淘汰明显失败的候选。
4. 对候选在原尺寸重新渲染并检查过渡和纹理。
5. 先排除违反硬约束的候选，再比较目标匹配、修改量和复杂度。
6. 保存选择理由、失败项与所有参数。

原图本来已达标时应允许“不需要调整”；不能要求每张图都必须产生变化。单纯最小化像素变化会偏向永远不调色，单纯最小化目标色差会过度修改，两者需要明确的约束关系。

## 11. 批量运行的可靠性

当前缓存只按文件是否存在或蒙版尺寸判断，有复用过时结果的风险。后续缓存键必须包括：输入内容、ICC/方向、参考或Profile、模式与强度、蒙版后端/质量、算法与检测器版本。

同名不同扩展名文件不能共用报告和蒙版路径；写结果应采用临时文件加原子替换；中断后不能把半成品视为完成。批量输出要分开candidate/review/rejected/approved，且失败不能阻断其它图片的诊断。

当前已有串行处理和简单跳过，但这些不等于已经实现上述可靠断点与审批机制。

## 12. Mac低负载运行方案

- 继续采用原生Python与Swift/Vision；当前不需要Docker、PyTorch或额外模型权重。
- 默认并发1，限制数学库线程，分割结果按可靠内容签名缓存。
- 小代理图估计参数，原尺寸分块应用变换；原尺寸质量检查不能完全省略。
- 不同时常驻多个大模型；若以后引入语义模型，先测内存、延迟、效果和许可证。
- 只有用户明确允许时才使用远程计算；原图不因“使用GitHub”而自动上传。

本轮第二组诊断包含7次处理、导出与隔离实验，约10秒，进程峰值驻留内存约578MiB。这个测量不代表所有分辨率、所有机器或系统总内存；高像素图、16位I/O和新增检测会增加开销，需重新测量。

## 13. Photoshop与使用方式

核心处理可直接完全由代码完成，不依赖Photoshop。Photoshop可以作为人工蒙版修正、对照检查和最终批准的可选工具。

单一全局LUT只能表示同一种颜色映射，不能同时完整表达“仅背景调整、皮肤另一条曲线、头发独立变化”的空间语义操作。可选导出应是各区域变换加蒙版，或明确标注适用范围的全局LUT，不能承诺一个LUT复现所有局部效果。

目前已提供命令行，没有完成可视化操作界面或Photoshop插件。

## 14. 开发顺序和验收出口

### P0：先解决错误放行

把当前accepted降级为内部指标；实现待复核与正式成图的隔离状态。没有完整专项检测与必要人工批准时，不得自动输出approved。优先验证缺失检测、检测异常、中断和旧缓存不能被当作成功。

### P1：输入、精度与受约束曲线

统一EXIF方向与ICC；建立真正高位深I/O路径；替换无约束亮度分段响应，验证平滑渐变、边界、零强度与色域行为。不得通过磨皮解决色带。

### P2：双图蒙版与背景模型

用可信蒙版过滤采样；用留出区域验证模型，处理构图差异与外推置信度。先复测已有全身图与半身图，不能只修一张。

### P3：皮肤、头发与商品保护

用少量人工确认区域建立可检查的基线，检验参考区域变化是否能正确影响目标区域、非目标区域是否被保护，再接自动分区。

### P4：候选选择与批量稳定

引入完整质量门控、候选比较、可靠缓存、结果签名、失败归档与人工批准。通过后再考虑轻量界面与更复杂算法。

### 必须建立的回归测试

| 类别 | 测试内容 | 通过依据 |
| --- | --- | --- |
| 身份变换 | 零强度、原图已达标、不同分块尺寸 | 规定工作空间下像素一致；无块缝 |
| 渐变 | 多方向、多肤色、多噪声水平、8/16位导出 | 无新增可见色带；专项指标与人工标签一致 |
| 蒙版 | 发丝、白衣、靠边人物、重叠、遮挡 | 不泄漏；低置信必须复核 |
| 人物对应 | 只改参考皮肤/头发或只改源图局部 | 对应区域合理响应；其它区域受保护 |
| 商品保护 | 深色牛仔、白色针织、条纹、鞋包 | 不发生未经允许的固有色或纹理改变 |
| 输出 | PNG/JPEG/高位深母版、重新读入、ICC | 文件正确；最终发布格式单独验收 |
| 缓存 | 改原图、Profile、模式、模型、检测器 | 必须失效重算；无同名覆盖 |
| 拒绝机制 | 缺检测、异常、全候选失败、审批过期 | 无法生成approved结果 |

实际照片需要覆盖多个拍摄批次、构图、肤色、服装和背景。训练/调参集与验收集分开。具体通过阈值要根据人工认可样片校准，目前没有足够样本支持“自动准确率”或“零伪影率”的数字承诺。
